# Копировщик сделок торгового счёта на счета Upscale

Отдельное приложение для участников. Участник подключает свой проп-счёт Upscale по API в Telegram-боте, а служба повторяет на этом счёте **все сделки торгового счёта бота**. Сейчас это счёт `upscale`: FIBO и SMC, риск 1%, ИИ бота допускает сетапы и ведёт позиции. Владелец управляет доступом и смотрит статистику в окне **CopierAdmin.exe**.

## Источник — торговый счёт бота (решение владельца 27.10.2026)

Копируются не стратегии, а счёт. Если ИИ бота одобрил вход, перевёл позицию в безубыток, подтянул стоп, закрыл половину или всю позицию, у участников происходит то же самое.

- **Источник** — книга счёта по HTTP на localhost, только чтение: `GET http://127.0.0.1:8787/api/accounts/feed?id=<счёт>&since_ts=<мс>`. Это панель бота, `format 1`, коммит `8443ac6` в боте.
- **Код счёта** — настройка в админке («Источник»), по умолчанию `upscale`.
- **Правки стратегий доходят до участников.** Счёт торгует на живом коде бота, и это решение владельца. Прежнее «бот участников не реагирует на правки бота» для этого источника отменено.
- **Изоляция кода остаётся.** `Copier/` ничего не импортирует из `Live_Bot` и не читает его файлы (`tests/test_isolation.py`). Служба работает от пользователя `copier` с `InaccessiblePaths=/opt/kraken`: закрыты файлы, а не порт.
- **Замороженный движок (`copier-engine`) остановлен 27.10.2026.** Код и данные лежат в `/opt/copier/engine*`. Включить снова: `systemctl enable --now copier-engine`.

## Как устроено

```
бот: счёт upscale (книга по 5-минутным свечам, ИИ ведёт) ── GET /api/accounts/feed (8787)
                                                              │ только чтение, раз в 20 с
copier (python -m copier.service) ── feed → follower → Upscale API (ключ участника)
                                   ├─ tg/      — Telegram участников (свой токен)
                                   ├─ admin_api — 127.0.0.1:8790 + токен → CopierAdmin.exe (ssh-туннель)
                                   └─ SQLite data/copier.db (ключи зашифрованы Fernet)
```

| В книге мастера | У участника |
|---|---|
| новая заявка | Лимит (или стоп-заявка `stop_market`, если `stop_entry`) по цене мастера, стоп на ордере; тейки по целям и долям. |
| заявка исчезла без позиции | Снять заявку. Если у участника она успела налиться, закрыть по рынку. |
| заявка стала позицией | Налив участника видит сверка: цены Upscale и бота различаются. |
| позиция без заявки | ИИ одобрил вход, когда лимит уже за рынком. Участник входит по рынку, если цена мастера ещё не за стопом и не за первой целью. |
| сменился `stop_loss` | Перенести стоп участника, только в сторону уменьшения риска. |
| уменьшился `remaining` | Тейк или «половина» ИИ: довести остаток участника до той же доли по рынку, если тейк на Upscale ещё не сработал. |
| позиция исчезла и есть строка в `closed` | Закрыть остаток по рынку. Причина словами: стоп, безубыток, цель, срок, решение ИИ, правила пропа. |
| событие ИИ в `instructions` | Сообщение тем участникам, у кого сделка по этой паре. |

Уже открытые позиции мастера на момент подключения или смены источника не копируются: вход по рынку в идущую сделку — это другая сделка.

Заявки мастера, которые ещё ждут налива, догоняются (`follower.catch_up`, с 27.10.2026): когда счёт начинает копировать — участника активировали, активный участник подключил счёт, снята пауза участника, счёта или общая пауза входов, — ему выставляются те же заявки по цене мастера. Условие — рынок Upscale ещё по ту сторону входа, где мастер ждёт (лимит: лонг — цена выше, шорт — ниже; стоп-вход — наоборот). Если цена уже у входа или за ним, заявка исполнилась бы сразу по рынку, не по цене мастера: она не ставится, причина — в отказах («при подключении…»). Заявку, которую участник уже получал (и, например, снял сам), второй раз не ставят.

**Риск** (решение владельца 27.10.2026): только в боте, в правилах счёта. Участник торгует тем же процентом от своего баланса, что и счёт-мастер (`rules.risk_pct`, сейчас 1%). Своего сторожа общей позиции и выбора риска у копировщика нет.

**Что ещё проверяется перед заявкой** (`sizing.py`):
- пара есть на Upscale, счёт активен и не заблокирован;
- одна сделка на пару на счёте (Upscale сливает позиции);
- без встречных позиций на счетах одного участника (правило Upscale);
- номинал не больше баланс × плечо (иначе Upscale не откроет; стоп не двигается);
- худший исход не пробивает дневной и общий лимит пропа **на счёте участника** (буфер 0.5%). Это защита его счёта от провала: этап у участника не совпадает с этапом мастера.

Каждый отказ пишется в журнал.

**Задержка:**
- книга опрашивается раз в 3 с: заявка мастера уходит участникам через несколько секунд, снятая снимается так же;
- сверка со счетами Upscale идёт раз в 10 с, а на наливе мастера запускается сразу;
- при входе берётся снимок счёта из сверки, если ему меньше 30 с, без лишнего запроса.

Медленнее только сам бот: его книга обрабатывает рынок по закрытым 5-минутным свечам (налив, безубыток, закрытия по сроку и ИИ), а допуск ИИ ждёт ответа модели. Раньше бота копировщик эти события не узнает. Стопы и тейки участников стоят на Upscale и срабатывают сразу.

**Предохранители ленты** (`feed.py`):
- позиции участников закрываются только по строке `closed`;
- новый этап счёта мастера, смена `format` или массовое исчезновение записей — заморозка до решения админа («Источник» → «Снять заморозку»);
- адрес не отвечает дольше 180 с (бот перезапускается) — новых входов нет, позиции держат стопы на Upscale;
- счёт мастера встал (`target`, `failed`) — новых входов нет.

## Установка и выкатка

Код заливается по ssh, без GitHub (репозиторий публичный): `export COPIER_SSH='ssh -i … -p … root@<сервер>'`, затем `bash Copier/ops/upload.sh`. Тесты идут на сервере до замены; если не прошли, служба остаётся на прежнем коде.

Первая установка (26.10.2026): `upload.sh --only`, затем на сервере `setup_server.sh <telegram-id>`, `COPIER_TG_TOKEN` в `/opt/copier/data/.env`, `systemctl start copier`. `COPIER_SECRET_KEY` из того же файла хранить отдельно.

Окну CopierAdmin нужен проброс на `127.0.0.1:8790`. Ключ `kraken-remote` в `/root/.ssh/authorized_keys` ограничен `permitopen`, поэтому к нему добавлен `permitopen="127.0.0.1:8790"`. Копия прежнего файла лежит в `authorized_keys.before_copier`.

Бот участников — @AIKrakens_bot. Ярлык «Копировщик — админка» лежит на рабочем столе (`Copier\desktop\dist\CopierAdmin.exe`).

## Повседневное

**Путь участника** (решение владельца 26.10.2026):
1. `/start` — приветствие, «мы работаем с Upscale», кнопка регистрации (`COPIER_SIGNUP_URL`) и «Готово».
2. Участник присылает ID на Upscale, затем API-ключ. Счёт с API Trading подключается сам, если такой один.
3. Статус «на проверке», владельцу приходит карточка: ID, владелец ключа по Upscale (✓ или «сверьте»), счёт.
4. Владелец ставит галочку «активен» в админке («Участники») или жмёт кнопку в карточке. Уровень берётся по счёту: реальный — полный, демо — демо. С этого момента копируются все новые сделки счёта-источника, а заявки мастера, ещё ждущие налива, выставляются сразу.
5. Если снять галочку, новые сделки не открываются, а уже открытые доводятся вслед за мастером.

| Задача | Как |
|---|---|
| Ссылка на бота для участников | Админка → «Участники» или `/admin` в боте. |
| Активировать или отключить | Галочка в строке участника или кнопки карточки в Telegram (`/requests`). |
| Посмотреть счёт-источник | Админка → «Источник»: позиции и заявки мастера, события счёта и решения ИИ, закрытые, копии у участников. |
| Сменить счёт-источник | Там же: код счёта и «Сменить». Книга должна отдаваться. |
| Аварийно | Админка → «Система»: пауза входов, «закрыть всё у всех». |

## Проверка на демо (до реальных счетов)

`python tools/probe.py`, затем `python tools/probe.py --fill`. Ключ демо-счёта кладётся в `Copier/.probe_key` (на сервере — `UPSCALE_API_KEY`, вывод — `PROBE_OUT`). Пройдено на демо 27.10.2026, ответы — `/opt/copier/data/probe/20261027_045724.json`:

- [x] лимит и `stop_market` принимают `stopTriggerPrice` и `takeTriggerPrice`; `sizeMode=base` + `baseSize` работает, `amount` — резерв (`amount=0` — отказ `amount_not_positive`). На исполнении из резерва берутся маржа по цене исполнения + комиссия + спред; не хватило — `canceled_by_error` / `insufficient_reserve_at_execution` (AVAX 27.10.2026: резерв ровно под маржу, рынок со спредом). Поэтому резерв = маржа + `COPIER_RESERVE_EXTRA_PCT` (3%), неистраченное возвращается. Замер на ARB: потрачено = маржа по индексу × 1.00063;
- [x] деталей одного ордера API не отдаёт — только история по тикеру `GET /orders/{acc}/{asset}/history` (`data`, `totalCount`, `errorCode`); по ней копировщик узнаёт, почему пропала заявка, и сообщает участнику и админу;
- [x] рыночный вход со стопом на ордере: после налива появляется отдельный ордер `type:"stop"` с `positionId` (= `idx` позиции) и `parentOrderId` (= ордер входа);
- [x] шагов цены и размера у рынков нет — цены и размеры в fp9 любой точности; плечо — `settings.maxLeverageByAccount` в fp9 по видам счёта (`{"0":5,"1":5,"2":2}`), какой вид у счёта — API не говорит, поэтому плечо перебирается сверху вниз; закрытость — `settings.isClosed/isPaused/isCloseOnly`;
- [x] лимиты в `/accounts/with-risk-status` — обычные проценты (`"5"`), а `consistencyRuleLimit` — доля в fp9 (`"300000000"` = 30%);
- [x] у позиции `entryPrice` НЕТ: вход = `notional ÷ size` (документация: notional — «size at entry price»); `direction` строчными (`long`);
- [x] на одну позицию ставится несколько `take`; `amount` у `take`/`stop` — размер в базовом активе;
- [x] `PATCH /orders/{id}` создаёт НОВЫЙ ордер с новым `id`, прежний — `canceled_by_update`: следующий перенос идёт по новому id;
- [x] закрытие — `take` с `triggerPrice "0"` и `amount` = размер; привязанные стоп и тейки снимаются сами;
- [x] `GET /positions/{id}` после закрытия: `status:"closed"`, `pnl` — разница цен БЕЗ комиссий, `fee` — все комиссии за жизнь позиции, `funding` — плюс получен, минус уплачен. Итог = `pnl − fee + funding`; цена выхода — `exchangedQuote ÷ exchangedBase` события `closePosition`.

## Риски

- **Правила Upscale о копировании.** 26.10.2026 владелец сообщил, что получил от Upscale разрешение. В админке на каждом счёте виден `antifraudStatus`.
- **Правило 30%** на счетах с API (`consistencyRuleRatio` в админке).
- **Ключ Upscale нельзя ограничить**: он даёт полные права. Хранится зашифрованным, участник может отозвать его в Upscale.
