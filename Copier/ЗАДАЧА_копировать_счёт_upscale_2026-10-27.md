# Задача копировщику: копировать торговый счёт `upscale`, а не стратегии

Передано из сессии торгового бота (live-bot) 27.10.2026. Код копировщика — ваш, в нём я ничего не менял.

## Решение владельца (27.10.2026, дословно по смыслу)

> Убрать выбор стратегий. Выбирать счёт, который создан в боте, копировать позиции с этого счёта и дублировать их всем, кто подключён к боту. Если ИИ переведёт сделку в безубыток или закроет её, у участников должно произойти то же самое. Копируем все сделки счёта, а не стратегии.

Это решение отменяет прежнее требование «бот участников не реагирует на изменения торгового бота» — для этого источника. Счёт торгует на живом коде бота, поэтому правки FIBO и SMC в боте теперь дойдут до участников. Скажите об этом владельцу один раз, когда будете показывать результат.

## Что уже сделано в боте

**Счёт** `upscale` («Upscale»), создан 26.10.2026 в 21:42 UTC, вид `manual` («проп по инструкциям» — книга ведётся по 5-минутным свечам самим ботом).

| Правило | Значение |
|---|---|
| Стратегии | FIBO (Фибоначчи часовая), SMC (обычная) |
| Риск на сделку | 1% |
| Дневной убыток | 5% (правило Upscale «Базовый») |
| Общая просадка | 10% (правило Upscale «Базовый», статичная от начала этапа) |
| Цель по прибыли | нет (0): при цели счёт остановился бы, и копирование встало бы у всех |
| Позиций одновременно | 4, в одну сторону — 3 (как сторож копировщика по умолчанию) |
| Депозит книги | 10 000 |
| ИИ ведёт счёт (`ai_control`) | да — локальная модель: допуск сетапа, раз в час безубыток (после +1R), подтянуть стоп, закрыть половину, закрыть всё |

Разница в дневном лимите: бот считает 5% от начала этапа, начиная с капитала на 00:00 UTC; Upscale считает от баланса на начало дня. Каждому участнику запас по правилам пропа проверяет ваш `sizing.py` со своим буфером — это остаётся.

Нет счёта — 404.

## Как события ложатся на счёт участника

| В книге мастера | У участника |
|---|---|
| новая заявка в `pending` | лимит (или стоп-заявка, если `stop_entry`) по `limit_price`, стоп на ордере, тейки по `targets`/`fractions` — как у вас сейчас |
| заявка исчезла, позиции по паре нет | снять заявку; если у участника налилось — закрыть по рынку |
| заявка → позиция по той же паре | налив (у участника налив видит сверка) |
| позиция появилась без заявки | вход по рынку: ИИ одобрил вход, когда лимит уже за рынком (instruction `market` или `ai`). Входить, только если цена не за стопом и не за первой целью. |
| `stop_loss` позиции изменился | перенести стоп участника, только в сторону уменьшения риска: безубыток после тейка, ИИ «безубыток» или «подтянуть» |
| `remaining` уменьшился | `tp_hit` вырос — тейк (если тейк участника не сработал, закрыть ту же долю по рынку); `ai_half` — ИИ закрыл половину: закрыть ту же долю по рынку |
| позиция исчезла, в `closed` есть её `trade_id` | закрыть остаток по рынку. `AI` — решение ИИ, `RULES` — сработали правила пропа мастера |

## Что убрать или поменять

1. Допуск стратегий в админке и выбор стратегий у участника → один источник: «Счёт бота: upscale» (код счёта — настройка, на будущее может быть другой).
2. Ленту из `engine_data/paper_state.json` и `paper_trades.jsonl` → опрос `feed` (у вас сверка 30 с — подойдёт). Предохранители оставить:
   - бот перезапускается (`restart_when_idle.sh`), и адрес на 1–2 минуты недоступен — это «лента молчит»: новых входов нет, позиции держат стопы на Upscale;
   - массовое исчезновение без строк `closed` — заморозка;
   - смена `format` — заморозка.
3. Движок `copier-engine` как источник больше не нужен. Остановить ли его, чтобы освободить процессор, решает владелец.
4. ИИ-куратор на Gemini теперь будет вести те же позиции вторым мнением, поверх ИИ бота. Предложите владельцу выключить его (`off`) или оставить в тени, чтобы позиции не вели двое.
5. Сторож общей позиции: мастер держит до 4 сделок по 1%, а предел риска 3% не пропустит четвёртую. Согласуйте с владельцем: поднять до 4% или считать риск из мастера.
6. Уведомления участникам: события ИИ берите из `instructions` с `kind == 'ai'` — заголовок и причина уже готовы.

## Задержки

Книга двигается по закрытым 5-минутным свечам, поэтому события мастера отстают на 5–10 минут. Модель на сервере медленная (хостинг отбирает процессор):
- допуск сетапа ИИ спрашивает в минуты 8–58 часа, лимит ждёт ответа до 2 ч;
- обзор позиций — в минуты 35–55 каждого часа, ответ занимает около 5 минут.
