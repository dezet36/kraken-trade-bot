# Установка на сервер

Три шага. Если что-то пойдёт не так, установщик сам скажет что именно и как
чинить — гадать не придётся.

## 1. Скопировать папку

Всю папку целиком — на сервер, в любой каталог. Например `/opt/kraken-bot`
или `C:\kraken-bot`.

## 2. Запустить установку

**Linux**

```bash
cd /opt/kraken-bot
chmod +x install.sh run.sh install_service.sh
./install.sh
```

**Windows**

```powershell
cd C:\kraken-bot
powershell -ExecutionPolicy Bypass -File install.ps1
```

Установщик проверит Python, создаст окружение, поставит зависимости, заведёт
каталог данных и положит туда `.env` из шаблона. После этого он попросит
вписать ключи биржи.

## 3. Вписать ключи и запустить снова

Откройте `bot_data/.env` и заполните:

```
TRADING_MODE=PAPER          начните с фантома, ордера на биржу не уходят
EXCHANGE=bybit
BYBIT_API_KEY=...
BYBIT_SECRET_KEY=...
STRATEGY=BOTH               обе стратегии одновременно, каждая со своим депозитом
RISK_PER_TRADE=0.5
```

Запустите установщик ещё раз — он прогонит проверку готовности: свяжется с
биржей, проверит ключи, права, риск и настройки. Пока в списке есть строка
`ОШИБКА`, бот запускать бессмысленно.

## Запуск

| | Linux | Windows |
|---|---|---|
| в текущем окне | `./run.sh` | `.\run.ps1` |
| окном с дашбордом | — | `.\run.ps1 -Desktop` |
| службой (автостарт) | `sudo ./install_service.sh` | `.\Live_Bot\install_service.ps1` |

Дашборд: **http://localhost:8787**

Служба поднимает бота при загрузке сервера и после падения. Логи:
`journalctl -u kraken-bot -f`.

## Где лежат данные

```
kraken-bot/
├── Live_Bot/        код       — можно перезаписывать целиком
├── venv/            окружение — создаётся установщиком
└── bot_data/        ДАННЫЕ    — здесь всё, что нельзя терять
    ├── .env                     ключи биржи и настройки
    ├── trades_journal.csv       журнал сделок
    ├── paper_trades.csv         фантомные сделки
    ├── positions_state.json     открытые позиции
    ├── runtime_settings.json    настройки с дашборда
    └── bot_log.txt              лог
```

**Резервная копия бота = копия `bot_data/`.** Всё остальное восстанавливается
из репозитория.

Каталог данных отделён от кода не для порядка, а по необходимости: раньше
всё лежало внутри `Live_Bot/`, и обновление копированием папки поверх старой
стирало журнал сделок вместе с состоянием позиций.

## Обновление

Три способа. Выбирается один раз — тем, как вы поставили бота.

### 1. Кнопкой на дашборде (если ставили из git)

Раздел «Управление» → «Обновление» → «Проверить» → «Обновить».

Работает, только если папка бота — git-репозиторий, а новый код уже
**отправлен на GitHub**. Собранная через `make_release.py` папка таким
репозиторием является: скрипт делает разреженный клон, внутри лежат только
рабочие файлы, но git внутри настоящий.

Что происходит при нажатии: код перематывается на свежий коммит, прогоняются
тесты, и если они не прошли — код возвращается на прежнюю версию сам. Данные
не трогаются: git их не видит.

### 2. Копированием новой папки (если git недоступен)

```bash
./update.sh /path/to/new-release        # папка
./update.sh /path/to/kraken-bot.zip     # архив
```

Скрипт проверит, что перед ним действительно сборка бота, сохранит старый
код рядом, заменит новый, доставит зависимости и прогонит проверку
готовности. Не прошла — скажет, чем вернуть старую версию.

`bot_data/` в список замены не входит вовсе: ключи, журнал сделок,
состояние позиций и настройки задеть физически нечем.

### 3. Вручную через git

```bash
cd /opt/kraken-bot
git pull --ff-only
venv/bin/pip install -r requirements.txt
systemctl restart kraken-bot
```

---

**Перезапуск после обновления обязателен при любом способе.** Python держит
загруженные модули в памяти: файлы на диске новые, а работает ещё старый код.

```bash
systemctl restart kraken-bot
```

Открытые позиции это переживают: они стоят на бирже со своими стопами, а
состояние лежит в `bot_data/` и читается при старте.

## Проверка версии

Какая версия сейчас работает — видно на дашборде в разделе «Управление»,
в панели «Обновление»: короткий номер коммита, дата и описание.

## Режимы

| | что делает |
|---|---|
| `PAPER` | фантом: сделки считаются со всеми издержками, на биржу не уходят |
| `DEMO` | демо-счёт биржи: настоящие ордера, ненастоящие деньги |
| `LIVE` | реальные деньги; запуск требует подтверждения с клавиатуры |

Начинайте с `PAPER`. Месяц фантома на живом рынке говорит о стратегии
больше, чем любой бэктест.

## Если что-то не работает

Первым делом — проверка готовности, она объясняет по-русски:

```bash
BOT_DATA_DIR=$PWD/bot_data venv/bin/python Live_Bot/doctor.py
```

Дальше — лог: `bot_data/bot_log.txt` или раздел «Журнал» на дашборде.

## Безопасность

Дашборд не имеет ни пароля, ни HTTPS. По умолчанию он слушает только сам
сервер (`127.0.0.1`), и управление разрешено только оттуда. Чтобы смотреть
его снаружи, пробросьте порт по ssh:

```bash
ssh -L 8787:localhost:8787 user@server
```

Открывать порт наружу без обратного прокси с паролем нельзя: любой
желающий сможет поднять риск на сделку или закрыть позиции.

Файл `.env` содержит ключи биржи. На Linux установщик ставит ему права
`600`. В резервные копии и в git он попадать не должен.
