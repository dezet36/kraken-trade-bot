# Установка на сервер (Linux)

Бот живёт на Linux-сервере под systemd. На ПК остаётся только окно
**KrakenRemote** — оно подключается к серверу по ssh-туннелю и показывает
панель; само ничего не торгует.

## 1. Один файл, с которого всё начинается

Скопируйте `bootstrap.sh` на сервер и запустите:

```bash
chmod +x bootstrap.sh
./bootstrap.sh                 # поставит в /opt/kraken-bot
./bootstrap.sh ~/kraken-bot    # или куда скажете
```

Установщик сам спросит биржу, режим торговли и ключи API и запишет их в
`bot_data/.env`. В конце предложит запустить бота службой.

Репозиторий закрытый, поэтому загрузчик спросит **токен доступа GitHub**.
Взять его: github.com → Settings → Developer settings → Personal access
tokens → Fine-grained tokens → Generate. Доступ — только к репозиторию
`kraken-trade-bot`, права — Contents: Read-only. Токен сохранится в
`bot_data/.git-credentials` и понадобится ещё раз при обновлениях: тем же
токеном пользуется кнопка «Обновить» на панели.

Повторный запуск загрузчика безопасен — он обновит код и не тронет данные.

Если папка с кодом уже на сервере (например, `git clone` руками):

```bash
cd /opt/kraken-bot
chmod +x install.sh run.sh install_service.sh
./install.sh
```

## 2. Ключи и проверка

Откройте `bot_data/.env` и заполните:

```
TRADING_MODE=PAPER          начните с фантома, ордера на биржу не уходят
EXCHANGE=bybit
BYBIT_API_KEY=...
BYBIT_SECRET_KEY=...
RISK_PER_TRADE=0.5
```

Ключи нужны и в фантоме: котировки берутся с биржи. Для PAPER и DEMO
подойдут ключи демо-счёта. Затем — проверка готовности, она объясняет
по-русски, что не так и как чинить:

```bash
BOT_DATA_DIR=$PWD/bot_data venv/bin/python Live_Bot/doctor.py
```

Пока в списке есть строка `ОШИБКА`, бот запускать бессмысленно.

## 3. Запуск

| | команда |
|---|---|
| в текущем окне | `./run.sh` |
| службой (автостарт, перезапуск при падении) | `sudo ./install_service.sh` |

Панель: **http://localhost:8787** на самом сервере. Логи службы:
`journalctl -u kraken-bot -f`.

**Модель ИИ — отдельной службой.** Стратегия LLM спрашивает модель через
`llama-server` (llama.cpp с MTP-ускорением), а не внутри бота:

```bash
git clone --depth 1 https://github.com/ggml-org/llama.cpp /opt/kraken/llama.cpp
cd /opt/kraken/llama.cpp && cmake -B build -DGGML_NATIVE=ON -DLLAMA_CURL=OFF     && cmake --build build --config Release -j 6 --target llama-server
cp /opt/kraken/code/Live_Bot/kraken-llm.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now kraken-llm
```

В `bot_data/.env` — `LLM_SERVER_URL=http://127.0.0.1:8788`. Модель — MTP-сборка
`Qwen3.6-35B-A3B-MTP-UD-Q3_K_M.gguf` в `bot_data/models/` (unsloth). Живость
сервера видна на вкладке «Разбор ИИ». Логи: `journalctl -u kraken-llm -f`.
Без `LLM_SERVER_URL` бот поднимает модель сам (llama-cpp-python) — вдвое
медленнее.

Есть и вариант в Docker (`docker-compose.yml`, `./start_server.sh`) — он
держит те же папки `Live_Bot/` и `bot_data/`; служба и Docker
взаимозаменяемы, одновременно их не запускают.

## Где лежат данные

```
kraken-bot/
├── Live_Bot/        код       — можно перезаписывать целиком
├── venv/            окружение — создаётся установщиком
└── bot_data/        ДАННЫЕ    — здесь всё, что нельзя терять
    ├── .env                     ключи биржи и настройки
    ├── paper_trades.csv         фантомные сделки
    ├── trades_journal.csv       боевые сделки
    ├── positions_state.json     открытые позиции
    ├── runtime_settings.json    настройки с панели
    ├── llm_calls.csv            разборы модели
    ├── llm_armed.json           взведённые планы модели
    ├── positioning/             ОИ, фандинг, дельта, ликвидации
    └── bot_log.txt              лог
```

**Резервная копия бота = копия `bot_data/`.** Всё остальное восстанавливается
из репозитория.

## Обновление

**Кнопкой на панели:** Настройки → Обновление → Проверить → Обновить. Код
перематывается на свежий коммит, прогоняются тесты, и если они не прошли —
код возвращается на прежнюю версию сам. Данные не трогаются: git их не
видит.

**Руками:**

```bash
cd /opt/kraken-bot
git pull --ff-only
venv/bin/pip install -r requirements.txt
systemctl restart kraken-bot
```

**Перезапуск после обновления обязателен.** Python держит загруженные
модули в памяти: файлы на диске новые, а работает ещё старый код. Страница
панели после выкатки перезагружает себя сама. Открытые позиции перезапуск
переживают: их состояние лежит в `bot_data/` и читается при старте, как и
взведённые планы модели.

Какая версия работает — видно в панели внизу слева (хеш коммита) и в
Настройки → Обновление.

## Режимы

| | что делает |
|---|---|
| `PAPER` | фантом: сделки считаются со всеми издержками, на биржу не уходят |
| `DEMO` | демо-счёт биржи: настоящие ордера, ненастоящие деньги |
| `LIVE` | реальные деньги; запуск требует подтверждения с клавиатуры |

Начинайте с `PAPER`. Месяц фантома на живом рынке говорит о стратегии
больше, чем любой бэктест. Пороги перехода — в `docs/Перед_реальным_счётом.md`.

## Окно на ПК (KrakenRemote)

`Live_Bot/build_remote_exe.ps1` собирает `KrakenRemote.exe`. При первом
запуске окно спрашивает адрес сервера, порт ssh и ключ; дальше держит
туннель само и переподключается при обрыве. Запускать можно сколько угодно
раз — работает одна копия, повторный запуск поднимает уже открытое окно.

## Если что-то не работает

Первым делом — `doctor.py` (выше). Дальше — лог: `bot_data/bot_log.txt`,
раздел «Диагностика» на панели или отчёт одним файлом (Диагностика →
Отчёт), который можно отправить целиком.

## Безопасность

Панель не имеет ни пароля, ни HTTPS. По умолчанию она слушает только сам
сервер (`127.0.0.1`), и управление разрешено только оттуда. Снаружи её
видно только через ssh-туннель — именно так работает KrakenRemote:

```bash
ssh -L 8787:localhost:8787 user@server
```

Открывать порт наружу без обратного прокси с паролем нельзя: любой
желающий сможет поднять риск на сделку или закрыть позиции.

Файл `.env` содержит ключи биржи и токен Telegram. Установщик ставит ему
права `600`. В резервные копии и в git он попадать не должен. Один токен
Telegram — один процесс: вторая копия бота с тем же токеном ломает опрос
обеим.
