**Дата:** 27.06.2026

**Статус:** активная разработка, DEMO-тестирование

## 1. ОБЗОР СИСТЕМЫ

**Kraken** — автоматизированный торговый бот на крипто-фьючерсах, реализующий стратегию Smart Money Concepts (SMC) в комбинации с сеткой Фибоначчи. Торгует перпетуальными фьючерсами на Bybit/BingX через CCXT.

### Стек технологий
- **Язык:** Python 3.13
- **Биржа:** Bybit Demo (планируется переход на BingX Live)
- **Подключение к бирже:** CCXT
- **Планировщик:** APScheduler (цикл каждые 5 минут)
- **Уведомления:** Telegram Bot API (текст + PNG-график)
- **Визуализация:** matplotlib + mplfinance (TradingView-стиль)
- **Логирование:** собственный logger + trade journal (CSV)

## 2. АРХИТЕКТУРА И ЛОГИКА СТРАТЕГИИ

### Многоуровневый анализ (3 таймфрейма)

```
4H  →  Определение тренда (EMA50 / EMA200)
1H  →  Поиск импульса A→B + зоны коррекции
5M  →  Подтверждение входа через слом структуры (BoS)
```

### Поток сигнала (pipeline)

```
Сканер (каждые 5 мин)
    └── 34 пары из пула
        └── [1H] find_recent_impulse (48 свечей)
            └── Фильтр: импульс ≥ 3% от цены
                └── Расчёт зон: Zone_A (38.2–61.8%), Zone_B (78.6–88.6%)
                    └── Инвалидация: цена не ушла за 88.6%
                        └── Текущая цена в одной из зон
                            └── [4H] HTF-фильтр: EMA50/EMA200
                                └── [5M] Detect BoS + объём ≥ 1.2× EMA20
                                    └── Расчёт Entry / SL / TP1-4
                                        └── Исполнение ордера
```

### Параметры стратегии

| Параметр | Значение |
|---|---|
| Таймфрейм основной | 1H |
| Таймфрейм входа | 5M |
| HTF тренд | 4H EMA50/EMA200 |
| Lookback импульса | 48 свечей (2 дня) |
| Минимальный импульс | 3% от цены |
| Риск на сделку | 1% баланса (фиксировано) |
| Плечо | 20× |
| Максимум позиций | 5 одновременно |
| TP1 | +18% от вершины импульса |
| TP2 | +27% |
| TP3 | +61.8% |
| TP4 | +100% (расширение 1:1) |
| Кулдаун после сделки | 12 часов на пару |
| Безубыток | После TP1 |
| Трейлинг | После TP2 |

### Риск-менеджмент
- Каждый TP закрывает 25% позиции
- После TP1: стоп автоматически переносится в безубыток
- После TP2: активируется трейлинг-стоп
- Software SL + биржевой SL (двойная защита)
- Максимальная экспозиция: 5 пар × 1% = 5% баланса

## 4. СИЛЬНЫЕ СТОРОНЫ

### S1 — Многоуровневая фильтрация
Три таймфрейма (4H/1H/5M) значительно снижают количество ложных сигналов. HTF-фильтр блокирует контртрендовые входы (BULLISH → не входим в SHORT).

### S2 — Чёткая логика входа
BoS-подтверждение с объёмом (≥ 1.2× EMA20) гарантирует что вход происходит только после реального слома структуры, а не случайного пробоя.

### S3 — Умный риск-менеджмент
Фиксированный риск 1%, каскадный выход (4 TP), безубыток после TP1, трейлинг после TP2 — классическая и проверенная структура управления позицией.

### S4 — Фильтр концентрации импульса
Если импульс тянется более 15 свечей, бот проверяет долю направленных свечей (≥ 60%). Это отсеивает боковые дрейфы, которые математически выглядят как импульс.

### S5 — Богатые Telegram-уведомления
- PNG-график с сеткой Фибоначчи, зонами, маркерами A/B, всеми уровнями
- Полный контекст: даты импульса, тип коррекции (классическая/глубокая), RR, объём
- UTC-метки времени для проверки по TradingView
- Уведомления по каждому TP, трейлингу, закрытию

### S6 — Масштабируемый пул пар
34 пары из разных сегментов рынка (BTC, ETH, L1/L2, DeFi, мемкоины). Сканирование происходит автоматически.

### S7 — Кулдаун и журнал сделок
Кулдаун 12 часов предотвращает повторный вход сразу после убытка. Все сделки записываются в CSV-журнал.

## 5. СЛАБЫЕ СТОРОНЫ И ТЕКУЩИЕ ПРОБЛЕМЫ

### W1 — Один импульс на пару (критично)
`find_recent_impulse` находит **один** импульс — по глобальному максимуму и минимуму за 48 свечей. Если в рынке есть несколько актуальных структур, бот видит только самую крупную. Возможна ситуация: более свежий и актуальный импульс игнорируется в пользу старого большого.

### W2 — Нет фильтра корреляции
Бот может одновременно торговать BTCUSDT, ETHUSDT, SOLUSDT — активы с корреляцией 0.8+. При одновременном открытии 5 позиций в одном направлении фактический риск может быть 4–5% баланса, а не 1%.

### W3 — Проблема с микроценовыми парами
SHIB, BONK, FLOKI торгуются по $0.000001–0.00002. Расчёт `position_size = risk / sl_distance` даёт миллиарды юнитов. Ошибки с установкой плеча и "Insufficient balance" уже зафиксированы на Bybit Demo.

### W4 — Нет фильтра по сессиям
Бот торгует круглосуточно. Сигналы в 3:00–5:00 UTC (мёртвый азиатский часов) значительно хуже чем в лондонскую/американскую сессию. Нет учёта времени суток.

### W5 — Нет учёта новостей и событий
Fed announcements, листинги, хардфорки, ликвидации — бот продолжает торговать в моменты экстремальной нерыночной волатильности.

### W6 — Плечо фиксировано (20×)
Одно и то же плечо для BTC ($60k, низкая волатильность) и PEPE ($0.000015, высокая волатильность) — неоптимально. Волатильные монеты требуют меньшего плеча.

### W7 — Нет восстановления состояния после перезапуска
При падении бота и перезапуске активные позиции не загружаются с биржи. Трейдинг продолжается вслепую без управления открытыми позициями.

### W8 — Нет веб-интерфейса мониторинга
Все данные только в логах и Telegram. Нет возможности посмотреть историю сделок, PnL-кривую, статистику по парам в удобном виде.

### W9 — Entry по рыночной цене (market order)
Вход всегда market-ордером. При низкой ликвидности или в моменты высокой волатильности проскальзывание может существенно ухудшить RR сделки.

### W10 — Один биржевой SL на всю позицию
После частичных закрытий на TP1/TP2 биржевой SL остаётся на исходный объём позиции. Потенциальная проблема с несоответствием размеров.

## 6. ИДЕИ ДЛЯ РАЗВИТИЯ (ROADMAP)

### ПРИОРИТЕТ: ВЫСОКИЙ

#### I1 — Мульти-импульсное обнаружение
Вместо одного импульса — топ-3 по качеству (размер × актуальность × концентрация). Торговать по лучшему из активных.

#### I2 — Фильтр корреляции
Перед открытием новой позиции проверять корреляцию с уже открытыми. Если в портфеле уже есть BTCUSDT LONG, не открывать ETHUSDT LONG. Разбить пары на группы (BTC-group, ETH-group, DeFi-group, мемы).

#### I3 — Восстановление позиций после перезапуска
При старте: загрузить открытые позиции с биржи (`fetch_positions`), сопоставить с внутренним состоянием, восстановить управление трейлингом и TP-уровнями.

#### I4 — Исключение несовместимых пар
Автоматически проверять при старте: `exchange.load_markets()` → фильтровать только `type=='swap'` или `type=='linear'`. SHIB/BONK/FLOKI либо исключаются, либо получают уменьшенное плечо.

#### I5 — Динамическое плечо на основе ATR
```
leverage = min(20, max(3, base_leverage / (ATR_14 / price * 100)))
```
Высоковолатильные монеты — меньше плеча автоматически.

---

### ПРИОРИТЕТ: СРЕДНИЙ

#### I6 — Фильтр торговых сессий
Добавить в config `ACTIVE_HOURS = [(7, 17), (13, 22)]` (UTC, Лондон + NY). Вне сессий — только управление позициями, новые входы заблокированы.

#### I7 — Limit-ордер на вход (вместо market)
После подтверждения BoS выставлять limit-ордер на 0.1–0.2% лучше текущей цены с TTL 2 минуты. Если не исполнился — пропустить. Улучшает среднюю цену входа.

#### I8 — 1D тренд как дополнительный фильтр
Добавить третий уровень фильтрации: дневной тренд по EMA20/EMA50. Торговать только если 5M BoS + 4H тренд + 1D тренд совпадают.

#### I9 — Добавление Score-системы для сигналов
Каждый сигнал оценивается по критериям:
- Размер импульса (% от цены)
- Концентрация импульса
- Объём на BoS (сколько × EMA20)
- HTF выравнивание (4H + 1D)
- Зона (Zone_A надёжнее Zone_B)
- Время суток (сессии)

Входить только при score ≥ X. Регулировать порог для управления частотой сигналов.

#### I10 — Backtesting-модуль
Изолированный backtester на исторических данных с возможностью перебирать параметры (MIN_IMPULSE_PCT, ZONE_A/B границы, VOLUME_CONFIRM_MULT, MIN_RR). Автоматический расчёт WR, PnL, MaxDD.

---

### ПРИОРИТЕТ: НИЗКИЙ / ПЕРСПЕКТИВА

#### I11 — Веб-дашборд
Flask/FastAPI + простой HTML. Показывать:
- Текущие открытые позиции
- PnL-кривую за период
- Статистику по парам (WR, avg RR, кол-во сделок)
- Последние сигналы (принятые и отклонённые)

#### I12 — Режим "только сигналы"
Опциональный режим: бот находит сигналы и присылает уведомление, но **не исполняет** ордер. Пользователь решает сам. Полезно для начала работы с реальным счётом.

#### I13 — Масштабирование позиции (Scale-in)
Входить 60% в Zone_A. Если цена опускается в Zone_B — добирать оставшиеся 40% с более выгодной ценой. Улучшает среднюю цену входа при глубоких коррекциях.

#### I14 — Интеграция новостного фильтра
Подключить CoinGecko или CryptoPanic API. За 15 минут до/после крупного события (Fed, CPI, листинг) — блокировать новые входы.

#### I15 — Мультибиржевое исполнение
Выбирать биржу с лучшей ликвидностью/спредом для конкретной пары в момент входа. Bybit для топовых пар, BingX для менее ликвидных.

## 8. ВЫВОД

Бот имеет **правильную архитектуру** и **валидную стратегическую основу**. Логика SMC + Fibonacci — проверенный подход с задокументированным бэктестом +26.90%. Риск-менеджмент построен корректно.

Основные векторы развития:
1. **Надёжность** — восстановление после перезапуска, фильтрация несовместимых пар
2. **Качество сигналов** — score-система, фильтр корреляции, сессионный фильтр
3. **Наблюдаемость** — веб-дашборд, расширенная аналитика
4. **Гибкость** — режим "только сигналы", scale-in, динамическое плечо

При реализации приоритетов I1–I5 ожидается улучшение WR и снижение просадки за счёт устранения ложных сигналов и некоррелированных одновременных позиций.
