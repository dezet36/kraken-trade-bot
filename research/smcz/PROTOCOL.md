# SMC с нуля (smcz) — протокол, записан до расчёта, 02.10.2026

Задача владельца: реализовать торговлю по концепции Smart Money с полного
нуля, не опираясь на прежний код и прежние выводы, и сделать её прибыльной.
Здесь записано, ЧТО и КАК меряется, до того как посчитано первое число.
Менять протокол после расчёта можно только дописью с датой и причиной.

## Данные

- Минутные свечи Binance USDT-M, 30 пар, 2021-01 … 2026-09
  (`research/binance_klines_1m_cache`, о/х/л/з, объём, объём покупок
  тейкеров, число сделок). Дыр нет.
- Старшие таймфреймы (5м, 15м, 1ч, 4ч, 1д) строятся из минуток по границам
  UTC. Исполнение заявок, стопов и целей проверяется ПО МИНУТКАМ.
- Торговля идёт на Bybit; цены Binance и Bybit на этих парах расходятся на
  доли базисного пункта — для R это несущественно.

## Периоды

| Имя  | Окно                     | Для чего                                     |
|------|--------------------------|----------------------------------------------|
| DEV  | 2021-01-01 … 2023-12-31  | поиск: модели, параметры, фильтры            |
| VAL  | 2024-01-01 … 2025-03-31  | проверка отобранного на DEV, без подгонки    |
| HOLD | 2025-04-01 … 2026-09-30  | контроль, ОДИН раз, после фиксации правил     |

Сделка относится к периоду по моменту постановки заявки.

## Издержки (Bybit, линейные перпетуалы)

- вход лимитом — мейкер 0.02%; вход по рынку — тейкер 0.055% + 0.02% проскальзывание;
- выход по цели лимитом — мейкер 0.02%;
- выход по стопу — тейкер 0.055% + 0.05% проскальзывание;
- выход по времени / по условию — тейкер 0.055% + 0.02%;
- фандинг — 0.01% за каждые 8 ч удержания, списывается ВСЕГДА (не в пользу);
- стресс: все издержки ×1.5.

Исполнение консервативно: лимит наливается, только если цена прошла СКВОЗЬ
него (low < вход для покупки); в минуту налива проверяется только стоп; если
в одной минуте задеты и стоп, и цель — считается стоп. Стоп ставится один раз
и не двигается (правило проекта).

## Модели (семейства)

Все элементы строятся с нуля в `research/smcz/structure.py`.

- A. Продолжение от ордер-блока: слом структуры (BOS/CHoCH) с импульсом →
  лимит в ордер-блок ноги (или имбаланс) в дисконте/премии → стоп за началом
  ноги → цель: ликвидность / кратное R.
- B. Снятие ликвидности и смена характера: вынос свинг-экстремума старшего ТФ
  с возвратом → CHoCH на младшем ТФ → вход от блока/имбаланса ноги смещения →
  стоп за экстремумом выноса → цель: противоположная ликвидность / кратное R.
- C. Межтаймфреймовая: зона интереса старшего ТФ (блок в сторону тренда) →
  подтверждение CHoCH младшего ТФ внутри зоны → вход от блока младшего ТФ.
- D. Ликвидность по времени: максимум/минимум прошлого дня, недели, азиатской
  сессии; вынос с возвратом в лондонскую/нью-йоркскую сессию.

Фильтры, допустимые в поиске: направление старшего ТФ, сила импульса (в ATR),
дисконт/премия, время суток (киллзоны), объём/поток тейкеров на импульсе.

## Правила отбора

Одна позиция на пару на модель: новая заявка не ставится, пока прежняя
висит или открыта.

На DEV по каждой модели — сетка ≤ ~300 вариантов. Отбирается не пик, а
устойчивая область: соседи по сетке тоже в плюсе. На VAL идут не более
3 вариантов от модели.

Вариант ПРИНЯТ, если одновременно:
1. VAL: среднее чистое R > 0, нижняя граница 95% бутстрепа по дням > 0
   (или ≥ 0 при ≥ 300 сделок с t > 2);
2. VAL при издержках ×1.5 — среднее R > 0;
3. на VAL в плюсе ≥ 55% пар с ≥ 10 сделками;
4. на DEV и VAL каждый календарный год не хуже −0.05R/сделку.
Затем HOLD — один прогон; принятый вариант должен дать среднее R > 0.

Если ни один вариант не проходит — так и записывается; прибыльность не
подгоняется под ответ.
