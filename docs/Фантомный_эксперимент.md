# Фантомная торговля: месячное сравнение двух стратегий

Режим, в котором бот принимает решения на живом рынке, но **не отправляет на
биржу ни одного ордера**. Нужен для одной задачи: за месяц выяснить, какая из
двух стратегий — «импульс + Фибоначчи» или Smart Money Concepts — зарабатывает
больше, и получить историю сделок, пригодную для разбора и доработки.

---

## Зачем отдельный режим, а не демо-счёт

На бирже по инструменту может быть только **одна** позиция. Значит, на любом
счёте — реальном или демо — стратегии дерутся за пары: фибо находит сетапов
заметно больше, и половину сетапов SMC просто не удалось бы открыть. Сравнение
получилось бы не «какая стратегия лучше», а «какая успела первой».

В фантомном режиме у каждой стратегии своя книга позиций и свой депозит. Обе
могут одновременно держать BTCUSDT, в том числе **в разные стороны**. Это
единственный способ сравнить их на одном и том же рынке.

Второе следствие: ключи API не нужны вообще. Рынок читается публичным
клиентом, а класс `PaperBroker` физически не содержит вызовов создания ордера —
отправить сделку на биржу этим кодом нельзя даже по ошибке.

## Запуск по иконке (настольное приложение)

Один раз создать ярлык:

```
powershell -ExecutionPolicy Bypass -File Live_Bot\install_desktop.ps1
```

Появится значок «Kraken — торговый бот» на рабочем столе и в меню «Пуск».
Двойной клик запускает бота и открывает **отдельное окно** программы: своя
кнопка на панели задач, без адресной строки и вкладок. Внизу окна — панель
«Журнал работы»: она заменяет консоль, по ней видно, что бот жив, даже когда
сделок нет неделю. Индикатор рядом с заголовком показывает состояние (зелёный —
работает, красный — упал с ошибкой).

Как открывается окно, по убыванию качества:

1. **pywebview** — настоящее нативное окно. Не обязателен, но если выполнить
   `pip install pywebview`, приложение подхватит его само;
2. **Chrome или Edge в режиме `--app`** — окно без браузерного обвеса, со своим
   профилем. Работает без установки чего-либо;
3. обычный браузер — крайний случай.

**Закрытие окна останавливает бота.** Состояние сохраняется, следующий запуск
продолжает с того же места, но для месячного прогона без присмотра надёжнее
консольный `start.bat` — окно можно закрыть случайно.

**Режим LIVE из окна не запускается.** Подтверждение реальной торговли требует
двойного ввода с клавиатуры, а у окна нет консоли; пропустить подтверждение
означало бы убрать защиту, ради которой оно и сделано. Для LIVE — `start.bat`.

Удалить ярлыки: тот же скрипт с ключом `-Remove`.

Собрать один переносимый `Kraken.exe` (нужен только для машины без Python):
`powershell -ExecutionPolicy Bypass -File Live_Bot\build_exe.ps1`, требуется
`pip install pyinstaller`.

## Запуск из консоли

В `.env` (в каталоге `BOT_DATA_DIR`, либо в `Live_Bot/.env`):

```ini
TRADING_MODE=PAPER          # фантомный режим
STRATEGY=BOTH               # обе стратегии одновременно

PAPER_START_BALANCE=10000   # стартовый депозит каждой стратегии
# PAPER_START_BALANCE_FIBO=10000    # если нужны разные депозиты
# PAPER_START_BALANCE_SMC=10000

DASHBOARD_PORT=8787
```

Запуск обычный — `python Live_Bot/bot.py` или `start.bat`.

Дашборд открывается на `http://localhost:8787`, из локальной сети — по IP
машины. Для доступа снаружи нужен проброс порта.

### Начать эксперимент заново

```ini
PAPER_RESET=true
```

Прошлое состояние и журнал не удаляются, а уходят в архив с меткой времени
(`paper_state.json.20260804_101500.bak`). После первого запуска флаг нужно
убрать, иначе счёт будет обнуляться при каждом старте.

Депозит, изменённый в `.env` **после** старта эксперимента, намеренно
игнорируется: доходность считается в процентах от начальной базы, и подмена
базы задним числом исказила бы всю статистику. В лог при этом идёт
предупреждение.

## Как считаются сделки

Модель сознательно пессимистичная — завышенный результат хуже заниженного.

| Что | Как считается |
|---|---|
| Вход | GTC-лимит, как в бою. Заполняется, когда 5-минутная свеча **касается** цены лимита |
| Комиссия входа | мейкер, `PAPER_FEE_MAKER` (0.02%) |
| Комиссия выхода | тейкер, `PAPER_FEE_TAKER` (0.055%) — стоп и тейк на бирже срабатывают рыночным ордером |
| Проскальзывание | `PAPER_SLIPPAGE_PCT` (0.05%) на стоповых выходах: стоп срабатывает, когда рынок уже бежит |
| Фандинг | по реальной ставке биржи на границах 8-часовых интервалов; при недоступности — `PAPER_FUNDING_RATE_8H` |
| Стоп и тейк в одной свече | засчитывается **стоп** |
| Размер позиции | `RISK_PER_TRADE`% от **текущего** депозита своей стратегии (доход реинвестируется) |
| Тайм-стоп, безубыток, частичные тейки | как в боевом режиме, из тех же настроек |

Про правило «стоп важнее тейка»: по свече OHLC порядок событий внутри неё
неизвестен. Трактовка в свою пользу — самый частый способ нарисовать
доходность, которой не было, поэтому спорная свеча всегда считается против нас.

**Задержка.** Обрабатываются только закрытые 5-минутные свечи, поэтому событие
фиксируется с опозданием до 5 минут. Цикл бота идёт с тем же шагом.

**Остановка бота не теряет сделок.** Состояние лежит в `paper_state.json`, и
при следующем запуске брокер догоняет пропущенные свечи.

## Что показывает дашборд

По каждой стратегии отдельно:

- **доходность в % от своего депозита** — главная цифра; в долларах сравнивать
  нельзя, если депозиты разные;
- максимальная просадка (считается от пика кривой, а не от старта);
- сделки, винрейт, profit factor, сумма R и ожидание в R на сделку;
- издержки — комиссии и фандинг отдельной строкой, чтобы было видно, сколько
  съедает трение;
- кривая доходности обеих стратегий на одном графике, в процентах.

Таблицы:

- **открытые позиции** — текущая цена, плавающий результат в долларах и в R,
  отдельно помечены ордера, которые ещё ждут входа;
- **закрытые сделки** — вход, выход, стоп, результат в деньгах, процентах и R,
  издержки, MFE/MAE, причина закрытия, сколько держали и **почему открылась**.

«Почему открылась» — не украшение. Для фибо это зона, HTF-тренд, размер
импульса и score; для SMC — тип зоны, confluence и список сработавших факторов.
Именно по этому полю потом видно, какие условия дают плюс, а какие только шум.

## Выгрузка истории

Кнопки в дашборде или прямые ссылки:

- `http://localhost:8787/api/export.csv` — `paper_trades.csv`, открывается в Excel;
- `http://localhost:8787/api/export.jsonl` — полный дамп по сделке;
- `http://localhost:8787/api/data` — то же, что видит дашборд, в JSON.

Файлы лежат в `BOT_DATA_DIR`. Для анализа:

```python
import pandas as pd
df = pd.read_csv('paper_trades.csv')

# Кто чего достиг
df.groupby('strategy')[['pnl_usd', 'pnl_r']].agg(['sum', 'mean', 'count'])

# Какие условия входа реально приносят деньги (SMC)
smc = df[df.strategy == 'SMC']
smc.assign(f=smc.factors.fillna('').str.split(', ')).explode('f') \
   .groupby('f').pnl_r.agg(['mean', 'count'])

# Куда уходит результат
df.groupby(['strategy', 'exit_reason']).pnl_r.agg(['sum', 'mean', 'count'])
```

Колонки `mfe_r` / `mae_r` — максимальный ход за нас и против нас в R за жизнь
сделки. По ним видно, где стоп стоял слишком близко, а где цель слишком далеко.

## Чего этот эксперимент не покажет

- **Ликвидность и реальное исполнение.** Фантомный лимит наливается целиком по
  своей цене. На большом объёме или тонкой паре так не будет.
- **Один месяц — короткая выборка.** При 30–40 сделках на стратегию разница в
  10–15% доходности статистически ничего не значит. Смотреть надо на сумму R,
  profit factor и форму кривой, а не на итоговый процент.
- **Один режим рынка.** Месяц — это один режим. Бэктест уже показал, что SMC
  ведёт себя по-разному на бычьем и медвежьем периодах.
