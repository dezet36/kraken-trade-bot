# Структура проекта и продукта: модули и план перехода (08.10.2026)

Владелец 08.10: «давай сделаем реорганизацию проекта и продукта, поделим его на
модули, чтобы потом не путаться… риск должен устанавливаться не в рамках
стратегий, а в рамках торговли, как тестовой, так и реальной, а стратегии должны
анализировать и давать сетапы для торговли».

Здесь — что есть сейчас, какой должна быть структура, где будет жить каждая
настройка и в каком порядке переходить, не останавливая бумажную торговлю.
Документ — план для согласования; код по нему ещё не менялся.

## 2. Принципы

1. **Стратегия даёт сетап, счёт решает про деньги.** Стратегия отвечает «что и
   где»: сторона, вход, стоп, цели, сколько живёт заявка, как сопровождать
   позицию. Счёт отвечает «сколько и можно ли»: риск, размер, депозит, пределы,
   какие стратегии и стороны допущены.
2. **Один исполнитель для бумаги и реала.** Заявка → позиция → выход проходят
   одну и ту же логику; бумага отличается только тем, что «биржу» заменяет
   симуляция по 5-минутным свечам. Исследования (стенды) — на том же ядре:
   стенд = тестовый счёт = реальный счёт.
3. **Данные — только чтение.** Модуль данных не знает про заявки, в нём нет
   ключей с правом торговли. Ключи торговли живут только в реальных счетах.
4. **Связи — в одну сторону и через договоры.** Данные ← Анализ ← Стратегии ←
   Исполнение ← Счета ← Интерфейсы. Нижний модуль не импортирует верхний.
   Между модулями ходят описанные объекты (снимок рынка, сетап, заявка,
   событие сделки), а не внутренности.
5. **У каждого модуля свои настройки, свой раздел конфигурации и свои тесты.**
   Настройка живёт там, кто по ней решает (таблица в разделе 5), и меняется
   только через свой модуль — с историей.
6. **Правила проекта сохраняются:** изоляция стратегий, стоп на уровне
   инвалидации, данные с возрастом, атомарная запись, риск 1% на тесте.

## 3. Модули

### 1. Данные — «получаем с бирж и сервисов»

**Делает:** получает с бирж и сервисов сырую информацию для торговли и хранит
её как есть: свечи (с кэшем на цикл), стакан, ленту, ликвидации, открытый
интерес, фандинг, доли лонгов, капитализации и доминацию, настроение (DVOL,
премия Coinbase), новости бирж; следит за свежестью и отказами (прочерк +
строка в журнал, торговля от источника не зависит).

**Настройки:** реестр источников — для каждого биржи и сервиса: адреса API,
запасные адреса, IP или прокси, ключ только на чтение (если нужен), предел
запросов, таймаут, что берём и как часто; вселенная пар (пул, порог оборота).

**Сейчас:** `exchange.py` (чтение: `make_market_client`, `fetch_ohlcv`,
`market_symbol`), `positioning.py`, `liquidations.py`, `trades_ws.py`,
`flow_data.py`, `market_cap.py`, `market_mood.py`, `news_feed.py`; в `config` —
`DATA_DIR`, пул пар, порог оборота.

**Не делает:** не считает признаки и структуру, не торгует.

### 2. Анализ — «собираем, считаем, передаём стратегиям»

**Делает:** раз за цикл собирает по каждой паре и по рынку **снимок рынка** —
одинаковый для всех читателей: свинги, сломы (BOS/CHoCH), ноги, ордер-блоки,
имбалансы, ликвидность, уровни, режим рынка, признаки потока, фандинг на момент
решения, рынок в целом (доминация, TOTAL, настроение); разметка для модели ИИ;
обзор рынка.

**Сейчас:** `market_structure.py`, часть I пакета `smc/` (свинги, структура,
ликвидность, имбаланс), `market_regime.py`, `flow_features.py`,
`positioning.latest/settled_funding`, `llm_market.py`, `llm_context.py`.

**Не делает:** не решает, что торговать, и не знает, кто его читает (правило
изоляции из CLAUDE.md переходит сюда без изменений).

### 3. Стратегии — «ищем сетапы»

**Делает:** по снимку рынка находит сетап и описывает его целиком: сторона,
вход (лимит, по рынку, стоп-заявка), стоп (уровень инвалидации), цели и доли,
срок жизни заявки, условия снятия (за B у FIB12, у цели), сопровождение
(безубыток, предел удержания), пауза после выхода, объяснение «почему», разметка
для графика, ожидание по замеру. Улучшение и проверка стратегий — здесь же
(связь с её протоколом в `research/`).

**Реестр стратегий** — одна запись на стратегию: код, имя для человека, таймфрейм,
статус (кандидат / принята / выключена), пары замера, ссылка на протокол и итог
замера, цвет и описание для панели. Новая стратегия встраивается одной записью
в реестре и своим пакетом — без правки общих файлов.

**Сейчас:** `strategy.py` + `pair_scanner.py` + часть `config` (старая ФИБО),
`smc/` (часть II — решения) + `strategy_smc.py`, `smcs/`, `fib12/`, `levels/`,
`rsibb/`, `liquidity/`, `strategy_*.py`, ИИ (`llm_notebook`, `llm_rules`,
`strategy_llm`, `llm_decide`, `llm_prompt`, `llm_grammar`), часть
`strategy_profile`, `setup_geometry`.

**Не делает:** не знает депозит, риск, размер позиции, пределы позиций, стороны,
допущенные владельцем, и комиссии конкретного счёта.

### 4. Тестовые счета — «торгуем на бумаге и собираем результаты»

**Делает:** торгует сетапы допущенных стратегий на виртуальных деньгах по
правилам счёта; ведёт журнал сделок и сетапов, отказы, тень, наблюдение после
выхода; считает статистику (R, доля выигрышей, просадка, по сторонам, парам,
периодам); сравнивает стратегии; даёт управлять настройками счёта и допуском
стратегий — с историей.

**Счёт:** депозит; риск на сделку (1% — правило теста); какие стратегии допущены
и с какими сторонами и парами; пределы (позиций всего, в одну сторону, на
стратегию, суммарный риск, дневной убыток); модель исполнения бумаги (комиссии,
проскальзывание, фандинг).

**Два вида:**
- **счёт стратегии** — как сейчас: по одному на стратегию, свой депозит — честное
  сравнение стратегий между собой;
- **счёт-репетиция** — несколько стратегий на одном депозите с настройками
  будущего реального счёта — проверить сочетание (корреляцию, просадку,
  загрузку) до денег.

**Сейчас:** `paper_broker.py`, `risk_gate.py`, `exit_plan.py`, `settings_store`
(депозит, риск, слоты, стороны, портфель), `config.PAPER_*`, `setup_journal`,
`trade_journal`, `refused`, `shadow`, `follow_up`, `scan_report`.

### 5. Реальные счета — «торгуем деньгами на бирже или в проп-компании»

**Делает:** подключение к бирже или проп-компании; торговля по тем же сетапам
через то же ядро исполнения; полная настройка счёта; сверка с биржей; отчёты.

**Счёт:** биржа и ключи с правом торговли (хранятся только здесь); тип (свой
счёт / испытание или счёт проп-компании); депозит и валюта; риск на сделку; на
день, неделю, месяц; максимальная просадка; плечо; пределы позиций (всего, в одну
сторону, на стратегию, по коррелированным парам); распределение по стратегиям;
цели (дневная, месячная, цель испытания пропа); правила пропа (дневной убыток,
общая просадка, минимум торговых дней, запрещённые часы и новости); какие
стратегии допущены (только прошедшие порог «бумага → реал»); аварийный
выключатель.

**Сейчас:** `trade_manager.py`, часть `exchange.py` (клиент с ключами),
`exchange_keys.py`, `live_costs.py`, `config` (`TRADING_MODE`,
`LIVE_CONFIRMED`, ключи, `LEVERAGE`). Отложенное к этому моменту — в
`docs/Перед_реальным_счётом.md` (корреляция позиций, пароль панели,
подтверждение LIVE, порог перевода стратегии, общие числа эпохи ФИБО в
`trade_manager`) — становится требованиями модуля.

### 6. Исполнение и учёт — общее ядро для тестовых и реальных счетов (новый)

**Делает:** жизнь заявки и позиции по сетапу: постановка, налив (лимит, по
рынку, «рынок уже за лимитом»), снятие (срок, уход за уровень, цель без налива),
стоп, цели и доли, безубыток, удержание, фандинг, комиссии; события сделки → в
журналы. Два способа исполнения: **симуляция** (по 5-минутным свечам — для
тестовых счетов и стендов) и **биржа** (реальные заявки — для реальных счетов).

**Зачем отдельно:** чтобы бумага, реал и стенд исследований вели себя одинаково
по построению, а не по договорённости (правило «исполнение = замер»).

**Сейчас:** логика размазана между `paper_broker`, `trade_manager`, `exit_plan`,
`research/smc_engine.py` и `research/smcz/sim.py`.

### 7. Интерфейсы — «управление и уведомления»

**Делает:** веб-панель, приложение KrakenRemote, Telegram (панель и
уведомления), графики сделок, проверка готовности (`doctor`), отчёт для разбора.
Читает модули через их отчёты; меняет настройки только через модуль-владельца.
Разделы — по модулям: Данные (здоровье источников), Анализ (обзор рынка),
Стратегии (сетапы, воронка, статус), Счета (тестовые, реальные), Настройки.

**Сейчас:** `dashboard.py`/`.html`, `telegram_bot/notify/panel/state`,
`tg_format`, `chart_generator`, `chart_frame`, `glossary`, `remote*.py`,
`doctor.py`, `report.py`.

### 8. Исследования — «лаборатория»

**Делает:** протоколы, стенды, кэши истории, отчёты. Использует пакеты стратегий
и ядро исполнения (симуляцию) — то же, что торгует, а не копии.

**Сейчас:** `research/` (стенды со своими движками: `smc_engine`, `smcz/sim`),
`docs/`.

### 9. Платформа — «сервер и общее»

**Делает:** загрузка настроек по модулям, журнал работы, атомарная запись,
дирижёр цикла (вызывает модули по порядку: данные → анализ → стратегии → счета;
своей логики не имеет), сервис модели ИИ (llama-server и клиенты), обновление и
выкатка (`updater`, `ops/restart_when_idle.sh`), журнал ошибок, службы сервера.

**Сейчас:** `bot.py` (дирижёр + ветки стратегий), `logger`, `csv_journal`,
`params_env`, `config` (общая часть), `llm_server/local/worker`, `updater`,
`error_log`, `ops/`.

## 4. Договоры между модулями

- **Снимок рынка** (Анализ → Стратегии): пара, время, закрытые свечи нужных
  таймфреймов, структура, уровни, режим, признаки потока, фандинг, рынок в
  целом; у каждого числа — возраст. Только чтение.
- **Сетап** (Стратегии → Счета): стратегия, пара, сторона, время, вход и тип
  входа, стоп, цели и доли, срок заявки, условия снятия, сопровождение
  (безубыток, удержание), пауза после выхода, «почему», разметка, ожидание по
  замеру. **Без размера, риска и денег.**
- **Решение счёта** (Счёт → Исполнение): сетап + размер позиции + номер счёта —
  либо отказ с причиной (в воронку отказов).
- **События сделки** (Исполнение → Учёт → Интерфейсы): поставлена, налита,
  цель, безубыток, стоп, срок, снята — с ценами, временем, комиссиями, фандингом.

## 7. План перехода (шаг за шагом)

**Как переходим, не ломая тест.** Бумажная торговля на сервере идёт всё время.
Каждый этап — отдельная выкатка; перед ним снимаются «отпечатки поведения»
(решения всех стратегий на одних данных — тест изоляции уже есть; повтор брокера
на записанных свечах — добавляется на этапе 0), после — сравниваются:
расхождение = ошибка переноса. Файлы переносятся с «мостиками» (старое имя
импортирует новое), мостики убираются в конце. Данные на сервере (журналы,
состояние) переносятся скриптом с копией. Тесты зелёные на каждом шаге.

| этап | что | объём | что получает владелец |
|---|---|---|---|
| **0. Страховка и уборка** | отпечаток брокера (повтор журнала на свечах); удалить пустые папки `grid/scalp/polymarket` и локальные данные августа из папки кода (после проверки); каркас пакетов | малый | чистая папка, защита от тихих поломок при переносе |
| **1. Реестр стратегий и договор «сетап»** | стратегии отдают сетап без денег; реестр вместо ~12 мест регистрации; цикл бота без веток по стратегиям | средний | новая стратегия = пакет + запись в реестре |
| **2. Деньги — в счета** | настройки счетов (`accounts.json`): у каждой стратегии свой тестовый счёт, как сейчас, — депозит, риск 1%, стороны, слоты, предел в одну сторону, портфель; из стратегий и их настроек деньги убираются; перенос текущих значений с историей | средний | риск, депозит и пределы задаются на счёте, а не в стратегии |
| **3. Данные** | реестр источников (адреса, запасные адреса, IP/прокси, ключи только на чтение, лимиты); `exchange.py` делится на чтение рынка и торговый клиент; сборщики переезжают; здоровье источников на панели | средний | видно и настраиваемо, откуда что берётся |
| **4. Анализ** | снимок рынка на цикл; стратегии читают только снимок и сами на биржу не ходят; структура `smc` часть I и разметка ИИ переезжают | средний | один расчёт на всех, стратегии проще |
| **5. Единое исполнение** | одна логика заявки и позиции для бумаги и биржи; `paper_broker` и `trade_manager` → ядро + два способа исполнения; журналы общие | **большой** (самый рискованный) | бумага ведёт себя как реальный счёт по построению |
| **6. Тестовые счета** | счёт-репетиция (несколько стратегий на одном депозите), управление счетами с панели, статистика и сравнение по счетам | средний | проверка сочетания стратегий до денег |
| **7. Реальные счета** | подключение биржи (сначала демо Bybit, потом малая сумма), проп-компании, политика риска счёта, цели, правила пропа, аварийный выключатель, сверка; пункты `Перед_реальным_счётом.md` | **большой** | торговля деньгами с полной настройкой риска |
| **8. Интерфейсы** | панель и Telegram — по модулям; настройки через модули-владельцы | средний | понятная панель |
| **9. Исследования на общем коде** | стенды используют пакеты стратегий и симуляцию ядра исполнения | средний | стенд = бот по построению |
| **10. Перенос старых файлов по папкам** | старые модули верхнего уровня (`strategy_*.py`, `paper_broker.py`, `smc/`, …) переезжают в пакеты своих модулей; импорты в коде, тестах и `research/` переписываются одним скриптом; эталоны держат поведение | средний | папки = модули |

Предлагаемый старт — этапы 0–2: они убирают главную путаницу (деньги в
стратегиях) и почти не трогают торговую логику. Этап 5 — до реальных счетов
обязательно.

**Почему перенос файлов — в конце (решение 08.10 при начале этапа 1).** Этапы
1–9 проводят ГРАНИЦЫ (реестр, договоры, счета, данные, снимок, исполнение);
новый код сразу ложится в новые пакеты, старые модули пока стоят на местах.
Переносить их по одному с «мостиками» опасно: у пакетов с подмодулями
(`from smc import params`) мостик создаёт вторую копию модуля, и правка
параметров в одной копии не видна в другой — тихое расхождение. Поэтому старые
файлы переезжают одним шагом в конце, скриптом по всему коду, тестам и
исследованиям, под контролем эталонов.

## 8. Решения владельца (08.10.2026)

1. **Модули — 9**, как в разделе 3.
2. **Тестовые счета — по одному на стратегию** (как сейчас); счёт-репетиция не
   нужна. Этап 6 — управление и статистика по счетам стратегий.
3. **Реальная торговля — несколько площадок:** свой счёт Bybit, проп-компания и
   другая биржа. Модуль реальных счетов строится общим: подключение через единый
   интерфейс биржи (ccxt), правила проп-компании — отдельным профилем счёта.
   Какие именно проп-компания и вторая биржа — уточнить к этапу 7.
4. **Весь план по порядку**, этапы 0–9, каждый — с проверкой «поведение не
   изменилось» и выкаткой.

Имя пакета платформы в коде — `infra`, а не `platform`: `platform` — модуль
стандартной библиотеки Python, и пакет с таким именем в `Live_Bot/` подменил бы
его для всех библиотек.
